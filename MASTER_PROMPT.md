## 1. Project Overview & Architecture
**Project Name:** CoMIT (Problem Statement ID: PS-1, Team: Team Nexus)
**Core Objective:** Build a smart, cooperative AI-driven intersection management system designed specifically for **mixed traffic** environments (connected vehicles, non-connected older vehicles, pedestrians, and emergency responders).

**System Architecture:**
1.  **Perception Layer:** 
    *   Fuses data from AI vision cameras (YOLOv11), GNSS positioning, and V2X communication.
    *   *Data Source Strategy:* Since physical hardware isn't available for the demo, we will use **synthetic data feeds generated by high-fidelity simulators (like SUMO or CARLA)**. This is an industry-standard approach for early-stage validation and is completely acceptable (and often more promising for controlled demos) than messy real-world data without hardware. We will utilize datasets like **V2X-Sim** to simulate the perception inputs.
2.  **Decision Layer:**
    *   A Reinforcement Learning (RL) agent analyzes the live (synthetic) traffic feed to dynamically adjust Signal Phase and Timing (SPaT).
    *   It prioritizes minimizing wait times and idling emissions.
3.  **Safety & Verification Layer:**
    *   A strict, rules-based safety check that intercepts and validates the RL agent's decisions to prevent conflicting green lights or unsafe edge cases.
4.  **Communication & Priority Layer:**
    *   Establishes a "Green Corridor" for emergency vehicles, clearing lanes preemptively.
    *   Sends real-time alerts via V2X to connected cars.
    *   **Innovation:** Uses plug-and-play retrofit voice modules to integrate older, non-connected vehicles into the smart ecosystem.

## 2. Dashboard UI/UX & Governance
The central dashboard governs the intersection and provides real-time oversight.

**Design System & Aesthetics:**
*   **Theme:** Modern, dark-themed, glassmorphism UI.
*   **Typography:** Clean, sans-serif fonts (e.g., Inter or Roboto).
*   **Colors:** Deep blacks/blues for the background, vibrant cyan and neon green for active signals, alert red for emergencies.

**Core UI Components:**
1.  **Live Intersection Digital Twin (The Map):** A top-down 2D/3D rendered map fed by the synthetic data. It visualizes:
    *   Vehicle blips (color-coded by type: CV, non-CV, Emergency).
    *   Live traffic light statuses with countdown timers.
    *   The highlighted "Green Corridor" when an ambulance approaches.
2.  **Telemetry & Impact Metrics:**
    *   Real-time CO2 emissions saved (kg).
    *   Average wait time reduction (%).
    *   Current traffic density and RL confidence score.
3.  **Localization / Internationalization (i18n):**
    *   **Requirement:** The entire UI/UX must seamlessly switch languages based on user preference or localization settings (e.g., English, French for Zéphyr, regional languages).
    *   *Implementation:* Use a localization framework (like `react-i18next` if using React) to store all strings in JSON files, allowing instant language toggling without page reloads.

## 3. Testing, Debugging, and QA Strategy
To ensure a robust demonstration, the following testing protocols must be implemented:

1.  **Simulated Stress Testing:**
    *   Inject extreme traffic density scenarios into the SUMO simulator to observe the RL agent's behavior under pressure.
2.  **Safety Layer Validation (Unit Tests):**
    *   Write strict unit tests that intentionally feed the Safety Layer "bad" decisions from a mock RL agent (e.g., green for intersecting lanes). Ensure the Safety Layer blocks 100% of these.
3.  **V2X Latency Injection:**
    *   Introduce artificial latency (e.g., 100ms - 500ms delay) into the synthetic V2X data stream to test if the system can still safely govern the intersection with delayed information.
4.  **Bug Sorting (Triage Protocol):**
    *   *P0 (Critical):* Safety layer failure, dashboard crashing, emergency vehicle not recognized. (Fix immediately).
    *   *P1 (High):* RL agent making suboptimal (but safe) decisions, localization strings missing.
    *   *P2 (Minor):* UI glitches, minor latency in map updates.

## 4. Phase 2 Vision: City-Wide Centralized V2X Ecosystem
*To scale from a single smart intersection to a fully connected city infrastructure, the following advanced capabilities outline the next phase of development:*

1.  **Centralized Predictive Routing & Dynamic Re-routing:**
    *   **Emergency Support:** When an ambulance route is detected, the central system broadcasts V2V (Vehicle-to-Vehicle) and V2I (Vehicle-to-Infrastructure) signals to civilian vehicles *miles ahead*, instructing them to reroute or pull over early.
    *   **Traffic Balancing:** The RL agent expands to a multi-agent system managing a grid of intersections, dynamically rerouting connected vehicles away from congestion zones via their in-dash navigation.
2.  **Infrastructure Monitoring (Pothole/Damage Detection):**
    *   The existing YOLO vision nodes on traffic cameras are upgraded to detect road damage and potholes.
    *   This data is fed to the central system to automatically update the city's maintenance queue and warn approaching drivers via the voice module.
3.  **Synchronized Navigation & GLOSA Voice Assistance:**
    *   The retrofit voice module evolves from simple alerts to intelligent navigation.
    *   It syncs with GLOSA (Green Light Optimal Speed Advisory) to give composite instructions: *"Take the next right to avoid damaged road. Maintain 40 km/h to catch the green light in 5 seconds."*
4.  **Admin Enforcement & Violation Dashboard:**
    *   The AI vision system tracks speed (via ByteTrack velocity calculation) and red-light running.
    *   Violations capture the vehicle's cropped image, timestamp, and speed data, pushing it to a secure **Admin Enforcement Portal** for review and automated ticketing, ensuring road order is maintained.
